## 项目按五块组织（按你想做的事找入口）

`gamer_ai/` 下 9 个入口脚本，**在 PyCharm 里右键 → Run 即可**。

> **编号规则（2026-10-15 重排，1~9 连续）**：编号 = 上手顺序，名字 = 干啥的。
> 以前跳号是因为几个脚本被合并/删除了，现在统一重排，顺带说明它们去哪了：
> 
> `4_速度覆盖度` / `7_时序诊断` 并进了 `5_评估.py`（`--coverage` / `--timing`）；
> `8_注意力可视化.py` 并进了 `5_评估.py --cam`（`--live` 是原来的实时模式）；
> `13_找图复活.py` 也删掉了 —— 复活已经映射成 **G 键**，`7_迭代采集.py` 现在直接按 G
> （模板图和证据图挪到 `旧仓库/旧找图复活/`）；
> `11_标注补数据`（cv2 窗口版标注）删掉了 —— 它的功能（含"用模型动作当标签"的 K 键）
> `8_标注界面.py` 的浏览器界面全都有。编号故意不重排，免得你熟悉的 `6_自动玩.py` 突然换号。

| 环节 | 脚本 | 干什么 | 要模拟器吗 |
|---|---|---|---|
| **① 设备调试** | `1_自检.py` | 抓帧是否有效、分辨率/裁剪框对不对、模拟器卡没卡死 | 要 |
| | `gamer_ai/tools/` | 游戏内存读取服务（frida）、抓帧后端、探针 | 要 |
| **② 数据采集** | `2_采集.py` | 边玩边录：每次按键存一张 37 帧胶片条（F8 暂停 / X 撤销 / F10 退出） | 要 |
| | `3_复核.py` | 删除坏样本 / 改正标错的标签 | 不要 |
| **③ 模型训练** | `4_训练.py` | 从零训练（EfficientNet-B0 + 6 帧早融合，本机 GPU） | 不要 |
| | `5_评估.py` | **看效果**：准确率、两类负样本、推理延迟、按速度分桶 | 不要 |
| | `5_评估.py --coverage` | 只看速度覆盖度（高速段采够了没有，原 `4_速度覆盖度.py`） | 不要 |
| | `5_评估.py --timing` | 只看时序诊断（模型比人提前多久开始动，原 `7_时序诊断.py`） | 不要 |
| | `5_评估.py --cam` | 看模型在看画面哪里（Grad-CAM，原 `8_注意力可视化.py`）；`--live` 实时 | 离线不要 |
| **④ 模型测试** | `6_自动玩.py` | 部署端：实时预测 + 发键 + 动作锁定（`--dry-run` 先空跑） | 要 |
| **⑤ 数据迭代** | `7_迭代采集.py` | 让模型自己玩，自动录下「它犯错的时刻」；被捕后按 **G** 复活 | 要 |
| | `8_标注界面.py` | **浏览器里人工标注/挑帧**：把 10_ 录下的失误片段标成能训练的标准样本 | 不要 |
| | `9_迭代训练.py` | 在初代模型上小学习率微调（旧+新混合、来源加权） | 不要 |

```
make_dataset/
├── README.md                     ← 本文件
├── .git/                         git 仓库
├── .idea/                        PyCharm 工程配置（解释器 wasd311）
│
├── gamer_ai/                        ★ 现役项目（只在这里干活）
│   ├── README.md                 ★ 上手教程，先看这个
│   ├── 常见问题.md                  报错排查 + 按键速查
│   ├── 进阶说明.md                  深入原理与实测数据
│   │
│   ├── 1_自检 2_采集 3_复核 4_训练 5_评估 6_自动玩 7_迭代采集 8_标注界面 9_迭代训练
│   ├── games/                    ★ 一个游戏一个文件：按键表 + 默认训练参数
│   │   └── subway_surfers.py        地铁跑酷（换游戏就复制它改改）
│   ├── core/                采集 / 训练 / 评估的实现代码（不用直接运行）
│   ├── tools/                    逆向工具 + 内存读取服务 + 区域档案管理
│   ├── templates/                找图复活用的模板图（key*.png / play*.png）
│   │
│   ├── profiles/                 ★ 区域档案：一块画面区域 = 一个目录
│   │   └── cs01/                 （当前区域；自检拉框保存时会自动建新的）
│   │       ├── geometry.json        分辨率和截图区域（相对比例，换分辨率自动对准）
│   │       ├── keys.json            ★ 这块区域的按键表（键 -> 类别），采集/训练/发键都读它
│   │       ├── profile.json         档案信息（名字/游戏/按键/时间/标定分辨率）
│   │       ├── dataset/             手动采集的数据（一个会话一个子目录）
│   │       └── runs/                训出来的模型（一个模型一个子目录）
│   │           └── <模型>/
│   │               ├── best.pt  model_meta.json
│   │               ├── 模型评估/     5_评估.py 的产物（含 attention/ 热力图）
│   │               └── 迭代数据/      ★ AI 自己跑出来的（跟着这个模型走）
│   │                   ├── 原始事件/      10_ 录的待标注素材
│   │                   ├── 正确操作/      模型做对时自动存的样本
│   │                   └── 碰撞操作/      8_标注界面.py 人工标完的样本
│   ├── dataset/                  只放自检产物 _selftest（没建档案时的老落点）
│   └── runs/                     只放找图复活的证据图 找图\（没建档案时的老落点）
│
└── 旧仓库/                        ★ 退役的东西，平时不用看（见 [旧仓库/README.md](旧仓库/README.md)）
    ├── 旧模型/                    5 个退役模型（4 个竖屏时代 + 1 个横屏训崩的）
    ├── 旧数据/                    meta.jsonl 的历史备份（竖屏数据已被删除）
    ├── 旧探针/                    早期内存逆向的探针脚本与日志
    ├── 旧对比图/                  CAM 对比图等一次性产物
    ├── 旧调试产物/                旧日志/标定截图（runs 里清出来的）
    └── 旧文档/                    项目分析报告.md（对已删除旧方案的分析）
```

**你在 PyCharm 里只会去运行 `gamer_ai/` 下那些编号脚本，别的都不用碰。**

> **一条龙（8 步）**：
> ① `1_自检.py` 拉框 → 起名 → 生成区域档案（分辨率+截图区域+**按键表**）
> ② `2_采集.py` 选档案（`--profile`），分辨率/区域/按键全自动适配；加类改档案的 `keys.json`
> ③ `4_训练.py <档案路径>` 训练（参数在本文件 `TRAIN` 里改）→ 模型进档案的 `runs/`
> ④ `5_评估.py`（`--cam` 看注意力、`--coverage`/`--timing` 两个专科检查）→ 产物进该模型的 `模型评估/`
> ⑤ `7_迭代采集.py` 让 AI 自己跑 → 正确/错误数据进该模型的 `迭代数据/`
> ⑥ `8_标注界面.py` 挑帧改标签 → 写回 `迭代数据/碰撞操作/`
> ⑦ `9_迭代训练.py` 微调 → 新模型另存一个目录（不覆盖初版）
> ⑧ `6_自动玩.py` 自动挑最新模型开玩
>
> **想加按键**：改 `gamer_ai/games/subway_surfers.py` 的 `ACTION_KEYS`（加一行一个动作类），
> 或临时 `python 2_采集.py --keys w,s,a,d,q,e,n`。采集/复核/训练/上线发键全自动跟上。
>
> **想换游戏**：复制 `games/subway_surfers.py` 成 `games/<你的游戏>.py`，改按键表和默认训练参数；
> 采集时 `--game <你的游戏>`，训练时改 `4_训练.py` 开头的 `GAME` 那一行。
> 部署不用改 —— `6_自动玩.py` 读模型自带的按键表（`model_meta.json` 的 `key_map`）。
>
> **改训练参数**：`4_训练.py` 开头就是【一】换游戏、【二】训练参数两块（轮数/学习率/
> 类别权重上限/数据来源权重…），改完直接 Run，不用记命令行。
>
> 数据/模型按**区域档案**分家：换一块画面区域（换分辨率、换横竖屏、换个窗口）就新建一个档案，
> 它的数据、模型、取景配套放在一起，互不干扰。详见
> [gamer_ai/README.md 第 1 步附](gamer_ai/README.md)。

## Python 解释器

全项目统一用 conda 环境 **`wasd311`**（Python 3.11）：

* 位置：`D:\Anaconda\envs\wasd311`
* 装了：torch 2.5.1+cu124（CUDA，能用显卡）、opencv、numpy、PIL、matplotlib、**frida**
* PyCharm 里切换：**File → Settings → Project → Python Interpreter → 选 `wasd311`**

> 还有另一个环境 `wasd_local`（Python 3.10）是老版本，留着当退路。
> 它**装不了 frida**，所以采集时想读游戏内存就必须用 `wasd311`。

## 一句话流程

```
设备调试      数据采集                      模型训练              模型测试
1_采集自检 → 2_采集数据 → 3_复核数据 → 5_训练模型 → 6_评估效果 → 9_自动玩
                          （挑掉坏的）              （看准不准）   （让它自己玩）
                                             6_ 还能加参数：
                                               --coverage 速度覆盖够不够
                                               --timing   动作是不是偏早

数据迭代（效果不理想时才走这圈）：
  9_自动玩 上场 → 10_迭代补数据 录下犯错的时刻 → 12_标注界面 人工纠正
       → 9_迭代训练（在旧模型上微调）→ 回到 5_评估 / 6_自动玩
```

慢慢来，第 2 步要多做几轮（多玩几局），后面才练得出来。详细步骤见
[gamer_ai/README.md](gamer_ai/README.md)。

## 版本管理

这个目录是 git 仓库（`初始提交: 跑酷数据采集与模型训练流水线`）。
被 `.gitignore` 排除的大件（只在本地磁盘）：`gamer_ai/profiles/*/dataset/`、`gamer_ai/profiles/*/runs/`、
`gamer_ai/dataset/`、`gamer_ai/runs/`、旧仓库/`（退役模型几百 MB）。
区域档案里的 `geometry.json` / `profile.json` **是要进版本控制的**（很小，而且"这块区域"本身就是配置）。

**删东西之前先 `git status` 看一眼** —— 被 git 管着的文件删了还能找回来，没被管的找不回来。

## 几个提醒

* **采集数据是最花时间的一步**，别急着训练 —— 每个动作类建议采到 200 个以上再开训
  （采集时的启动横幅会直接告诉你还差多少）。
* 横屏/模型输入几何（`game_res` / `game_crop` / `frame_w`）必须和采集时一致，
  否则模型看到的画面就不一样了 —— 详见 [gamer_ai/进阶说明.md](gamer_ai/进阶说明.md)。
* 例：`python 4_训练.py --dry-run` 可以先看这次会用到哪些会话，不会真的开训。
