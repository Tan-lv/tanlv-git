## 一、这个项目在干什么（大白话）

一句话：**它录下你玩游戏时的操作，然后学着替你玩。**

就像教小孩玩游戏：你先握着他的手玩几局，他在旁边盯着看；看得够多了，他就自己上手。
这里「看」的就是**游戏画面**，「上手」的就是**按方向键**。

具体分三段：

| 阶段 | 干的事 | 用到哪几个脚本 |
|---|---|---|
| **① 采集** | 你正常玩，程序在边上不停截图，同时盯着键盘 —— 你按了哪个键、在第几帧按的，全记下来 | `1` `2` `3` `4` |
| **② 训练** | 把成千上万条「画面 → 该按哪个键」喂给一个神经网络，让它自己总结规律 | `5` `6` |
| **③ 部署** | 程序自己截屏 → 问模型 → 帮你在游戏里按键，循环往复 | `9`（`7` `8` 是排查用的） |

> 技术上这叫**行为克隆**（Behavior Cloning），属于「模仿学习」。你不用懂这个，知道它在模仿你就够了。

## 二、先认识 5 个词

后面到处都会用到，先花一分钟记住：

| 词 | 什么意思 |
|---|---|
| **样本** | 一条记录 = 一张图 + 「这时候该按什么键」。这是训练的最小单位 |
| **会话（session）** | 一次采集的成果，存成 `dataset/` 下的**一个文件夹**，名字是采集时的时间戳 |
| **标签** | 每个样本的正确答案，一共 6 种：**A**（左）/ **D**（右）/ **N**（不动）/ **Q**（道具等动作键）/ **S**（下滚）/ **W**（上跳） |
| **取景（区域）** | 「游戏画面里的哪一块」喂给模型。以**比例**存在 `geometry.json` 里，所以换分辨率、横竖屏都自动对准，只选一次 |
| **负样本** | 专门教模型「**这时候不该按键**」的样本（都属于 N 类）。其中两类是训练时程序自动合成的，不用你手动采 |
| **胶片条** | 一个样本存的其实不是一张图，而是一张**长条图**：把按键前后 1.2 秒里的 **37 帧**画面横着拼在一起。训练时程序从里面挑 6 帧叠起来喂给模型 |

> 为什么要存成胶片条？因为「该不该换道」光看一张静止画面判断不了，
> 得看障碍物是不是在靠近 —— 那是**动态**信息，必须靠连续几帧才看得出来。

### 第 1 步 · 采集前自检

**干什么**：确认能抓到活的游戏画面、模拟器有没有卡死、裁剪框对没对准。

**怎么跑**

```powershell
python 1_自检.py
```

**成功的样子**：打印出抓帧 fps（正常 40 左右）和几张带裁剪框的调试图。

> ⚠️ **每次采集之前都要先跑通这一步。** 它报「画面完全没有变化」就是模拟器卡死了，
> 重启模拟器再说。

#### 第 1 步附 · 取景（区域）只需要选一次

自检开始时会**弹出一个窗口**，用鼠标拖两个对角，框住你要让模型看的那块游戏画面。
窗口里有三种颜色的框，别搞混：

| 颜色 | 意思 |
|---|---|
| 🟢 绿框 | 程序**自动认出来**的游戏画面范围（模拟器的黑边/工具栏不算） |
| 🟡 黄框 | **你鼠标拖出来的**框（可能不是标准比例） |
| 🔵 蓝框 | 锁定 240:293 比例**吸附后真正会用**的框 ← **看这个** |

> 为什么要有蓝框：模型最终吃的是 224×224，落盘帧的比例决定了「有效视野」。
> 所以比例必须锁死成 240:293；你拖的框如果不是这个比例，程序会自动把它调整到
> 最接近的合规框（黄框和蓝框就会不一样）。**蓝框才是采集和部署时实际用的**。

**拖完怎么保存**：按 `s`（窗口里没有按钮 —— OpenCV 的窗口不支持按钮和输入框）。
按 `s` 后这个窗口会关掉，紧接着弹出一个**命名小窗**，在里面：

1. 给这块区域**起个名字**（默认会填 `横屏_1280x720` 这种，可以直接用）；
2. 想写备注就写（可留空）；
3. 点【**确定保存**】← 这才是那个「确定」按钮（也可以直接按回车）。

**确定保存之后会发生什么**：自动建出一个区域档案目录

```
gamer_ai/profiles/<你起的名字>/
    geometry.json    这块区域（相对比例，换分辨率/横竖屏也能自己对准）
    profile.json     档案信息（名字 / 创建时间 / 标定分辨率 / 备注）
    dataset/         以后用这块区域采到的数据，全放这里
    runs/            用这些数据训出来的模型，全放这里
    events/          7_迭代采集.py 录下来的待标注事件
```

并且它会被设为**当前区域**：之后 `2_`/`5_`/`6_`/`9_`/`10_` 不加参数就都用它。

> **现役就有一个现成的档案**：`gamer_ai/profiles/cs01/`（横屏第一版，2026-10-15 从
> `gamer_ai/dataset` + `gamer_ai/runs` 归位过来的，里面是 2662 个样本和模型 `横屏_v1`）。
> 想再开一块新区域（换分辨率、换横竖屏、换个模拟器窗口），就再跑一次自检拉框命名。

**换一块区域 = 换一个档案**：不同区域的数据和模型天然分开，不会互相串。

| 想干的事 | 怎么做 |
|---|---|
| 新建/切换区域 | 再跑一次 `1_自检.py` 拉框命名；或 `python tools\管理区域档案.py --use 名字` |
| 看有哪些区域 | `python tools\管理区域档案.py` |
| 临时用某个区域 | 给脚本加 `--profile 名字`（例如 `python 2_采集.py --profile cs01`） |
| 单独调区域、不跑整套自检 | `python tools\鼠标选裁剪框.py`（`--png 某张截图.png` 可以不开模拟器） |
| 没有选任何区域时 | 仍然用老位置：`gamer_ai/dataset`、`gamer_ai/runs`、`gamer_ai/geometry.json` |

**换分辨率 / 横屏竖屏 / 换模拟器**：因为存的是**比例**，程序每次启动都会重新探测游戏画面
在窗口里的实际位置和大小，再按比例换算出裁剪框 —— 实测 1962×1115 的窗口里游戏画面
从第 1 列开始（并不是水平居中），也能自己对准。

### 第 2 步 · 采集数据（最花时间的一步）

**干什么**：你进游戏关卡，正常玩；程序在后台把「画面 + 你的按键」录下来。

**怎么跑**（在 PyCharm 的 Parameters 里填）

```
--session run01 --hook-state
```

或者命令行：

```powershell
python 2_采集.py --session run01 --hook-state
```

`--session run01` 是这次采集的名字，成果会存到 `dataset/run01/`。
`--hook-state` 表示直接读游戏内存判断「现在是不是在跑酷」，比看画面准得多。

**采集时按这些键**（在采集器窗口里按）

| 键 | 作用 |
|---|---|
| `n` | **手动标记一个「此刻该什么都不做」的样本** —— 和 WASD 一样按下才记 |
| `X` | **撤销**：删掉最近落盘的 5 个样本。连按最多 5 次，停手 5 秒后次数重新计满，整场不限总次数 |
| `F8` | 暂停 / 继续采集（过场动画、菜单、死亡结算时按一下） |
| `F9` | 自动补 N 开关（默认关，开了会限速 1.5 秒一次） |
| `F7` | 把最近 3 秒导出成图片，核对时序用 |
| `F10` / `Esc` | 退出 |

**你要做的**：进关卡，正常玩，死了就继续下一局，玩够 10~20 分钟。**一局尽量玩久一点**
（速度上来之后的画面才是模型最需要的）。

**产出**：`dataset/run01/` 里出现 `meta.jsonl`（记录清单）和一堆 `.jpg`（胶片条）。

> 采集时怎么玩才练得好，看下面第七节「采集建议」。

### 第 3 步 · 复核数据

**干什么**：把采坏的样本挑出来删掉，或者改正标错的标签。

**怎么跑**

```powershell
python 3_复核.py
```

|---|---|

### 第 4 步 · 看速度覆盖度（已并入第 6 步，可选但推荐）

> ★ 2026-10-15：原来这里是独立脚本 `4_速度覆盖度.py`，现在合并进 `5_评估.py`：
> **`python 5_评估.py --coverage`**（不填参数就用当前区域档案的数据）。

**干什么**：游戏会越跑越快，如果数据全是慢速段的，模型一进高速段就会撞死。这一步告诉你数据够不够全。

**看什么**：报告末尾会说覆盖均匀还是不均匀。如果警告「最高速段只占 5.2%（建议 >= 10%）」，
就回去再玩几局、每局玩得更久一点。

> 训练开始时也会自动打印一份速度分布（`[speed]` 那几行），所以急着开训的话可以跳过这步。

### 第 5 步 · 训练模型

**干什么**：让神经网络从你的数据里学规律。**全部在本机跑，不联网、不需要服务器。**

**怎么跑**

```powershell
python 4_训练.py
```

有**当前区域档案**时（结构整理后默认就是 `cs01`），数据自动取档案的
`profiles/cs01/dataset/`，模型也自动存到 `profiles/cs01/runs/` —— **什么都不用填**。

想指定别的数据：

```powershell
python 4_训练.py --profile 别的区域名                  # 换一个区域档案
python 4_训练.py --session dataset/run01 dataset/run02  # 直接点名几个会话（这个优先）
```

> 既没有当前档案、又没给参数时，才回去用文件开头那个 `DATA_DIRS`（现在指向
> `profiles\cs01\dataset`，是"档案指针丢了"时的兜底）。

**要跑多久**：RTX 4060 Laptop 上大约 **3 分钟一轮**，默认最多 60 轮、连续 15 轮没进步就自动停。
所以完整跑一次可能一到两小时。屏幕上有一条**实时进度条**，五秒刷一次。
想先快速试一下，加 `--epochs 5`。

**产出**：`runs/<名字>/` 目录，名字自动生成为 `会话名_时间戳`，里面有

| 文件 | 是什么 |
|---|---|
| `best.pt` | **最终模型权重**（效果最好的那一轮） |
| `model_meta.json` | 部署要用的参数，`6_自动玩.py` 读它 |
| `log.txt` | 完整训练日志 |
| `curves.png` | 训练曲线图，可以直接打开看 |
| `history.csv` / `metrics.json` | 每一轮的指标数字 |

### 第 6 步 · 看效果

**怎么跑**

```powershell
python 5_评估.py
```

不填参数时它自动挑「效果最好的模型 + 最新的会话」。

**重点看这 4 个数字**（这才是判断能不能上线的关键，光看准确率会被骗）：

| 指标 | 什么意思 | 期望 |
|---|---|---|
| **换道动画负样本 → N** | 角色正在换道动画里，模型有没有管住手不再按方向键 | 越高越好，> 0.90 |
| **该换道却输出 N** | 本来该按方向键、模型却不动 —— 这种错**游戏里直接撞死** | 越低越好，< 10% |
| **障碍还远负样本 → N** | 障碍刚出现、还早，模型有没有忍住 | 越高越好 |
| **单张推理延迟** | `6_自动玩.py` 要跑到 40fps，每帧只有 25ms 预算 | < 25ms |

它还会按**游戏速度分桶**打印准确率与「该换道却输出 N」—— 高速段才是上线后的真实水平。

> 想量全量（不受划分影响）：
> `python 5_评估.py --profile cs01 --split all`（不给 `--sessions` 就用档案里的数据）。
>
> 这个脚本还兼了两个「专科检查」（原来是独立的 `4_` `7_` 两个脚本，2026-10-15 合并进来）：
>
> | 加的参数 | 看什么 | 大概多久 |
> |---|---|---|
> | `--coverage` | 速度覆盖度：高速段采够了没有 | 几秒 |
> | `--timing` | 时序诊断：模型比人早多久开始动、提高阈值的代价 | 全量 10~20 分钟；加 `--limit 300` 约 1 分钟 |
>
> 例：`python 5_评估.py --timing --limit 300`

## 五点五、加按键 / 换游戏 / 改训练参数

### 1. 想多监听几个按键（采集时多一个动作类）

按键表是**唯一来源**，改一处全都跟着走（采集监听、采集横幅、复核、标注、训练类别、上线发键）。

**推荐：改游戏配置文件** `gamer_ai/games/subway_surfers.py`（一个游戏一个文件）：

```python
ACTION_KEYS = {          # 动作键：按下 = 采一个该类样本；上线时模型预测到就真的按这个键
    "w": "W", "s": "S", "a": "A", "d": "D", "q": "Q",
    "e": "E",            # ★ 加一行就是一个新动作类
}
MARKER_KEYS = {"n": "N"} # 纯标记键：游戏里没映射，只用来标"此刻别动"
```

**临时试采**（不改文件）：`python 2_采集.py --keys w,s,a,d,q,e,n`
（纯键名=类别名自动大写；也可以写 `e=跳` 显式指定类别名。）

> 加完键记得先采够样本再训练：训练会自动**剔除样本太少的类**（`min_train_samples`），
> 太少的类硬训会把模型带崩 —— 地铁跑酷的 E 类就是这么翻车的。

### 2. 换一个游戏

一个游戏 = `games/` 下的一个文件（里面是**按键表** + **默认训练参数**）：

1. 复制 `games/subway_surfers.py` → `games/<你的游戏>.py`，改 `NAME` / `ACTION_KEYS` / `MARKER_KEYS` / `TRAIN`；
2. 采集：`python 2_采集.py --game <你的游戏>`（它会记住当前游戏）；
3. 训练：把 `4_训练.py` 开头的 `GAME` 改成 `"<你的游戏>"`；
4. 部署不用改：`6_自动玩.py` 读**模型自带**的按键表（`model_meta.json` 的 `key_map`），自动按对键。

看有哪些游戏：`python 2_采集.py --list-games`

### 3. 改训练参数（不用记命令行）

`4_训练.py` 开头就是【一】换游戏、【二】训练参数两块，改完直接 Run：

```python
GAME = "subway_surfers"          # 【一】换游戏只改这一行

TRAIN = {                        # 【二】常用训练参数
    "epochs": 60,                # 训练轮数
    "batch_size": 32,
    "lr": 1e-3,                  # 学习率
    "class_weight_max": 5.0,     # 类别权重上限（0 = 不截断，会爆）
    "min_train_samples": 10,     # 少于这么多样本的类别直接不训
    "source_weight": None,       # 新旧数据权重，如 "旧会话=1.0,迭代数据=2.0"
    "select_metric": "macro_f1", "patience": 15,
}
```

优先级：**命令行 > 这里的 TRAIN > `games/<游戏>.py` 的 TRAIN**。想给某个游戏一套自己的
默认值就改那个游戏文件；只想这一次不同就改这里的数字。`--dry-run` 会把最终生效的参数打出来。

> **数据迭代这一圈**（效果不理想时才走）：
> `7_迭代采集.py` 让模型自己玩并录下失误 →
> `8_标注界面.py` 在浏览器里挑帧打标签（**目录默认就是当前区域档案的**：

>

## 七、采集建议（想练得好，重点看这段）

| 建议 | 为什么 |
|---|---|
| **每类攒到 800~1000 个样本** | A/D/N/S/W 五个数都得到这个量级，否则模型会偏向多的那类 |
| **每一局尽量玩久一点** | 游戏会越跑越快，高速段的画面才是模型最缺、最需要的；开局几秒的数据价值很低 |
| **分 3~5 局采，每局一个会话名** | 速度覆盖更均匀，划分训练/测试时也不容易互相污染 |
| **别在菜单、死亡结算里采** | 那些画面会教坏模型。忘了暂停就用 `3_复核.py` 按 `f` 批量删 |
| **攒齐了再训练** | 训练需要所有会话一起做「按时间段均衡划分」；本机一轮 3 分钟，攒够一次练完最省事 |

**已经踩过的坑**：早期几批数据速度中位数只有约 10 px/秒，最快也就 27~41 px/秒，
高速段占比不到 1%。结果就是**模型在高速段基本必死**。所以后面采集一定要玩得久。

## 附：和旧版的区别

旧版是 `caiji.py` / `shuju.py` / `trian.py` / `auto_wasd.py` 四个平铺脚本，已经全部删除。
主要问题与现在的改法：

| 旧问题 | 现在怎么解决 |
|---|---|
| 按下按键**之后**才截图（延迟 100~300ms），存的是动作已经发生的画面 | 抓帧线程常驻，按键只记时间戳，事后从环形缓冲**回溯**取帧 —— 结构上不可能取到动作之后的画面 |
| 每个样本只有一帧，分不清「该换道」和「正在换道」 | 每样本存 37 帧连续画面，训练时取 6 帧叠成 18 通道 |
| 随机划分，相邻帧泄漏到验证集，指标虚高 | 按时间段均衡划分 |
| 不知道「别动」信号怎么给 | N 类三个来源：手动按 `n` + 换道动画合成负样本 + 障碍还远合成负样本 |
| 部署时在换道动画里重复触发 | 模型侧学会输出 N + 部署侧 320ms **同方向**动作锁定 |
| 游戏越来越快导致分布漂移 | 记录每个样本的速度、出覆盖度报告、可按速度重加权 |
| 采集失误无法补救 | `X` 键现场撤销 + 事后复核工具 |
| 抓帧依赖 ADB（本机会挂起） | PrintWindow 直接抓窗口，实测 40~56fps |
| 不知道游戏状态 | 直接读 IL2CPP 内存里的 `GameController` 状态变量 |
