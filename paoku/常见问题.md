## A. 抓帧 / 模拟器

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 自检报「**画面完全没有变化**」 | 模拟器卡死了（本机出现过两次，伴随虚拟机进程消失、`adb devices` 为空） | **重启模拟器**。这不是代码问题 |
| 抓帧 fps 只有十几（正常 40 左右） | 别的程序在抢 CPU | 关掉浏览器 / 暂停 PyCharm 的索引（File → Invalidate Caches 那个索引进程） |
| 采集到一半画面不动了 | 模拟器窗口被最小化了 | PrintWindow 在最上层遮挡时没问题，但**最小化时画面会停**。把窗口恢复出来 |
| 自检说裁剪框没对准 | 游戏分辨率/窗口大小和配置不一致 | 检查模拟器分辨率是否被改过；裁剪框以整窗截图为基准 |

> 采集前**每次都先跑 `1_采集自检.py`**。它 4 秒钟就能告诉你画面是活的还是死的。

## B. 状态服务（frida）相关

`--hook-state` 让采集器直接读游戏内存里的 `_isInPlaystate` / `_isAlive`，
比看画面准得多（撞车时刻能精确到那一帧）。它依赖一个后台「状态服务」进程。

**好消息：正常情况下你什么都不用管。** 采集器加了 `--hook-state` 之后会自动：
先检查 adb server → 检查设备连接 → 检查 frida-server（没跑就拉起来）→ 检查端口转发 → 启动状态服务。

正常会看到：

```
[IL2CPP] 状态服务没在跑，用 ...\wasd311\python.exe 自动拉起 ...
[IL2CPP] 状态服务已就绪 (127.0.0.1:47800)，用时 3.0s
[IL2CPP] 状态服务已连接  inst=0xade28820  当前 inPlay=0 alive=1
```

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报「**adb 里没有可用设备**」 | 模拟器没启动，或设置里 ADB 调试没开 | 启动模拟器；在模拟器设置里打开 ADB 调试 |
| 报「**frida-server 起不来**」 | 模拟器重启后 frida-server 就没了 | 见下面的手动命令 |
| 状态服务**闪一下就没了** | 早期版本用 `os.execv`，会被 PyCharm 回收控制台。**现在已改成子进程转发**，如果你还遇到，直接双击 `tools\run_state_server.bat` | 用 bat 启动 |
| 状态服务**自己退出了** | 它是**服务**，不是跑完就结束的脚本 | 看到「就绪」之后**不要点停止**，一直挂着。心跳停了才说明真的挂了 |
| 游戏更新后状态读不到了 | 类名/字段偏移变了 | 需要重新逆向（看 [tools/README.md](tools/README.md)） |

**手动重拉 frida-server**（自动失败时的兜底）：

```powershell
D:\leidian\LDPlayer9\adb.exe shell "su -c 'nohup /data/local/tmp/frida-server -D &'"
```

**只想看状态**（不采集）：双击 `tools\run_state_server.bat`，它每 10 秒打一次心跳：

```
[心跳] 已运行     10s   inPlay=0 alive=1 paused=0   已响应查询 5 次
```

## C. 采集时的操作

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 玩了两分钟，各类计数还是 0 | ① 误按了 `F8` 在暂停状态；② 还在「等开局中」（没进关卡） | 看状态栏末尾写的是不是「已暂停」；进关卡跑起来 |
| 跑完一看全是菜单画面 | 过场动画/菜单时忘了按 `F8` 暂停 | 用 `3_复核数据.py`，按 `f` 逐个跳到可疑样本、按 `d` 批量删 |
| 不小心按了个错的键，不想删整个会话 | | 按 `X` **撤销**：删掉最近落盘的 5 个样本。连按最多 5 次，停手 5 秒后次数重新计满，整场不限总次数 |
| `X` 按了好多次，删多了 | `X` 的语义是「删掉最近 5 个样本」，按 5 次就是 25 个 | 撤销是**不可逆**的（没有 git）。删多了只能重新采。所以按 `X` 前先想清楚 |
| 忘了这次的会话叫什么 | | 会话名就是你填的 `--session`；没填的话是时间戳。看 `dataset/` 下最新的文件夹 |
| 想采「此刻该不动」的样本 | | 按 `n`（和 WASD 一样，按下才记）。或者开 `F9` 让它自动补 |

> 采集时**不要在菜单里按键**。菜单里按 W 也会被记成一个「该跳」的样本，是纯噪声。

## D. 复核数据

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 运行 `3_复核数据.py` 后卡住不动 | 它在等你输入会话目录 | 在下面的 Run 控制台里输入 `dataset/run01` 回车。或者在 Parameters 里预先填好 |
| 窗口里中文显示成方块 | `cv2.putText` 画不了中文，项目里已改用 PIL + 微软雅黑 | 正常现象，不用管 |
| 删完之后训练报样本数不对 | | 复核是直接改 `meta.jsonl` 的，重新跑训练即可，不用改别的 |

## E. 训练

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **`MemoryError`** | Windows 上每个 DataLoader worker 光 import torch 就要约 600 MB。8 个 worker 再加预取缓冲就上 10 GB | 加参数降下来：`python 5_训练模型.py --workers 2 --batch-size 16 --prefetch 1` |
| `unrecognized arguments: --xxx` | **参数填到别的脚本上了** | 比如 `--no-cam` / `--dry-run` 是 `9_自动玩.py` 的；`--speed-balance` 是训练的。对照 [README.md](README.md) 第五节的脚本速查表 |
| `ImportError: attempted relative import with no known parent package` | 你直接运行了 `collector/` 里的文件 | **只运行 `paoku/` 下编号的那 9 个脚本**，它们负责把路径配好 |
| 报 `ModuleNotFoundError: torch` | 解释器不是 `wasd311` | PyCharm 右下角切解释器 |
| 训练特别慢、显卡几乎不动 | 数据管道跟不上（GPU 能吃到 424 样本/秒，管道只供 60 样本/秒，显卡 85% 时间在空转） | 已开「分组打乱」优化过一轮（+27%）。想再快就减少 `--workers` 之外的干扰进程 |
| 训练 loss 不降 / 准确率乱跳 | 数据太少或标签太乱 | 先跑 `6_评估效果.py` 看混淆矩阵；类别样本数太少就回去补采 |
| 想中途停掉 | | 直接 Ctrl+C 或点 PyCharm 的停止。已经跑完的轮次会存在 `runs/<名字>/` |
| 训练结果目录一大堆 | | 删掉不用的 `runs/<名字>` 即可，删之前确认没有 `9_自动玩.py` 在指着它 |

**关于训练时间**：RTX 4060 Laptop 上大约 3 分钟一轮，默认 60 轮上限 + 连续 15 轮没进步自动停。
第一次可以先加 `--epochs 5` 试跑，确认流程通了再完整跑。

## F. 自动玩

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 `找不到 ...\model_meta.json` | `MODEL_DIR` 指向的目录不对，或者那个模型没训完 | `python 9_自动玩.py --list-runs` 看有哪些能用的，把名字填对 |
| 模型**动作太早**（障碍还远就换道） | 行为克隆的通病，模型没有人的反应延迟 | 加 `--delay-ms 30`（**不要超过 50**，会和连按冲突）。根治办法是补采数据，见 [进阶说明.md](进阶说明.md) |
| 连着按 WA / WS / AA **发不出来** | 动作锁定拦掉了 | 现在 `--lockout-ms` 只锁**同一个方向**：A 之后再按 A 要等 320ms，但 A 之后按 D/W/S 立刻放行。默认已修好 |
| 一直重复触发同一个方向键 | 换道动画里模型又输出了方向键 | 这是「换道动画负样本」要解决的问题，看 `6_评估效果.py` 的第一个指标 |
| 开着 CAM 窗口很卡 | 每次热力图都要多做一次反向传播 | 加 `--no-cam`，或者把 `--cam-every` 调大（默认 4 帧一次） |
| 不想录视频却生成了视频 | | 视频**默认就是关的**。想录才加 `--record` |
| 想让它先别按键，只看预测 | | `python 9_自动玩.py --dry-run` |
| 跑一会儿自己停了 | | 加 `--run-seconds 60` 之类是主动限时；否则看窗口里打印的报错 |

## G. 按键速查

### 采集时（`2_采集数据.py` 的窗口）

| 键 | 作用 |
|---|---|
| `F8` | 暂停 / 继续（过场动画、菜单、死亡结算时按） |
| `X` | 撤销：删掉最近落盘的 5 个样本。连按最多 5 次，停手 5 秒后重新计满，**整场不限总次数** |
| `F7` | 把最近 3 秒导出成图片，核对时序用 |
| `n` | **采一个 N 类样本**（和 WASD 一样按下才记）—— 标记「此刻该什么都不做」 |
| `F9` | 自动补 N 开关（默认关闭；开了会限速 1.5 秒一次，并避开 WASD 按键附近的帧） |
| `F10` / `Esc` | 退出 |

### 复核时（`3_复核数据.py` 的窗口）

| 键 | 作用 |
|---|---|
| `n` / 空格 / `→` | 下一个 |
| `d` / `Delete` | 删除这个样本 |
| `1` `2` `3` `4` `5` | 改标签（对应 A / D / N / S / W） |
| `f` | 跳到下一个可疑样本（会自动绕回开头） |
| `q` | 保存退出 |

### 注意力可视化实时模式（`8_注意力可视化.py --live`）

| 键 | 作用 |
|---|---|
| `q` / `Esc` | 退出 |
| 空格 | 暂停 |
| `m` | 切换 Grad-CAM / 显著图 |
| `s` | 存图 |

## H. 报错关键词速查

把报错信息里的关键词拿来对：

| 关键词 | 大概率是 | 去看 |
|---|---|---|
| `MemoryError` | worker 太多 | [E. 训练](#e-训练) |
| `unrecognized arguments` | 参数填错脚本 | [E. 训练](#e-训练) |
| `attempted relative import` | 跑了 `collector/` 里的文件 | [E. 训练](#e-训练) |

## 还没解决的？

把这几个信息抄下来，就能快速定位（也方便问别人）：

1. **哪一步**出的问题（第 1~7 步里的哪一步）
2. **完整报错**（结尾十几行，不是开头）
3. **当时的参数**（`--session` / `--run` 之类）
4. `python -c "import torch; print(torch.__version__, torch.cuda.is_available())"` 的输出
