# 地铁跑酷 · 让 AI 自己玩游戏

这是本项目的主文档。**第一次来就从这里往下看，照着做一遍就能跑通。**

遇到报错 → [常见问题.md](常见问题.md)　想搞懂原理 → [进阶说明.md](进阶说明.md)

---

## 一、这个项目在干什么（大白话）

一句话：**它录下你玩游戏时的操作，然后学着替你玩。**

就像教小孩玩游戏：你先握着他的手玩几局，他在旁边盯着看；看得够多了，他就自己上手。
这里「看」的就是**游戏画面**，「上手」的就是**按方向键**。

具体分三段：

| 阶段 | 干的事 | 用到哪几个脚本 |
|---|---|---|
| **① 采集** | 你正常玩，程序在边上不停截图，同时盯着键盘 —— 你按了哪个键、在第几帧按的，全记下来 | `1` `2` `3` `4` |
| **② 训练** | 把成千上万条「画面 → 该按哪个键」喂给一个神经网络，让它自己总结规律 | `5` `6` |
| **③ 部署** | 程序自己截屏 → 问模型 → 帮你在游戏里按键，循环往复 | `9`（`7` `8` 是排查用的） |

> 技术上这叫**行为克隆**（Behavior Cloning），属于「模仿学习」。你不用懂这个，知道它在模仿你就够了。

## 二、先认识 5 个词

后面到处都会用到，先花一分钟记住：

| 词 | 什么意思 |
|---|---|
| **样本** | 一条记录 = 一张图 + 「这时候该按什么键」。这是训练的最小单位 |
| **会话（session）** | 一次采集的成果，存成 `dataset/` 下的**一个文件夹**，名字是采集时的时间戳 |
| **标签** | 每个样本的正确答案，一共 5 种：**A**（左）/ **D**（右）/ **N**（不动）/ **S**（下滚）/ **W**（上跳） |
| **负样本** | 专门教模型「**这时候不该按键**」的样本（都属于 N 类）。其中两类是训练时程序自动合成的，不用你手动采 |
| **胶片条** | 一个样本存的其实不是一张图，而是一张**长条图**：把按键前后 1.2 秒里的 **37 帧**画面横着拼在一起。训练时程序从里面挑 6 帧叠起来喂给模型 |

> 为什么要存成胶片条？因为「该不该换道」光看一张静止画面判断不了，
> 得看障碍物是不是在靠近 —— 那是**动态**信息，必须靠连续几帧才看得出来。

## 三、开始前，先确认这 4 样

| # | 要确认的 | 怎么确认 |
|---|---|---|
| 1 | **雷电模拟器 LDPlayer9 已启动** | 安卓桌面能正常显示 |
| 2 | **《地铁跑酷》已打开** | 停在游戏主界面就行，采集时再进关卡 |
| 3 | **PyCharm 解释器是 `wasd311`** | 右下角看，或 File → Settings → Project → Python Interpreter |

> [常见问题.md](常见问题.md) 的「B. 状态服务」一节。

## 四、第一次跑，照着这些步骤做

> 下面的步骤编号和脚本编号基本对应：**第 1~6 步依次用脚本 1、2、3、4、5、6，最后一步用脚本 9**。
> 脚本 `7`（时序诊断）和 `8`（注意力可视化）是**可选的排查工具**，不在主线流程里，
> 等你觉得「效果不对」的时候再回头看 [进阶说明.md](进阶说明.md)。

### 【PyCharm 用法先看这里】

本项目的脚本大多数**不需要参数**，PyCharm 里右键 → **Run** 就行。

需要参数的那几个（主要是第 2 步），这样填：

> **Run → Edit Configurations… → 在 `Parameters` 那一栏里填参数 → OK**

之后正常右键 Run，参数就会带上。

---

### 第 1 步 · 采集前自检

**干什么**：确认能抓到活的游戏画面、模拟器有没有卡死、裁剪框对没对准。

**怎么跑**

```powershell
python 1_采集自检.py
```

**成功的样子**：打印出抓帧 fps（正常 40 左右）和几张带裁剪框的调试图。

> ⚠️ **每次采集之前都要先跑通这一步。** 它报「画面完全没有变化」就是模拟器卡死了，
> 重启模拟器再说。

---

### 第 2 步 · 采集数据（最花时间的一步）

**干什么**：你进游戏关卡，正常玩；程序在后台把「画面 + 你的按键」录下来。

**怎么跑**（在 PyCharm 的 Parameters 里填）

```
--session run01 --hook-state
```

或者命令行：

```powershell
python 2_采集数据.py --session run01 --hook-state
```

`--session run01` 是这次采集的名字，成果会存到 `dataset/run01/`。
`--hook-state` 表示直接读游戏内存判断「现在是不是在跑酷」，比看画面准得多。

**采集时按这些键**（在采集器窗口里按）

| 键 | 作用 |
|---|---|
| `n` | **手动标记一个「此刻该什么都不做」的样本** —— 和 WASD 一样按下才记 |
| `X` | **撤销**：删掉最近落盘的 5 个样本。连按最多 5 次，停手 5 秒后次数重新计满，整场不限总次数 |
| `F8` | 暂停 / 继续采集（过场动画、菜单、死亡结算时按一下） |
| `F9` | 自动补 N 开关（默认关，开了会限速 1.5 秒一次） |
| `F7` | 把最近 3 秒导出成图片，核对时序用 |
| `F10` / `Esc` | 退出 |

**你要做的**：进关卡，正常玩，死了就继续下一局，玩够 10~20 分钟。**一局尽量玩久一点**
（速度上来之后的画面才是模型最需要的）。

**产出**：`dataset/run01/` 里出现 `meta.jsonl`（记录清单）和一堆 `.jpg`（胶片条）。

> 采集时怎么玩才练得好，看下面第七节「采集建议」。

---

### 第 3 步 · 复核数据

**干什么**：把采坏的样本挑出来删掉，或者改正标错的标签。

**怎么跑**

```powershell
python 3_复核数据.py
```

它会弹提示问你要复核哪个会话，输入 `dataset/run01` 回车即可。
（也可以在 Parameters 里直接填 `dataset/run01`）

**复核时按这些键**

| 键 | 作用 |
|---|---|
| `n` / 空格 / `→` | 下一个 |
| `d` / `Delete` | 删掉这个样本 |
| `1` `2` `3` `4` `5` | 改成 A / D / N / S / W |
| `f` | 跳到下一个「可疑样本」（按 `d` 删掉后自动跳下一个） |
| `q` | 保存并退出 |

**最值得删的**：菜单画面、死亡结算画面、明显标错的（比如该按 W 却记成 A）。

---

### 第 4 步 · 看速度覆盖度（可选但推荐）

**干什么**：游戏会越跑越快，如果数据全是慢速段的，模型一进高速段就会撞死。这一步告诉你数据够不够全。

**怎么跑**（Parameters 里填会话目录）

```powershell
python 4_速度覆盖度.py dataset/run01
```

**看什么**：报告末尾会说覆盖均匀还是不均匀。如果警告「最高速段只占 3.8%」，
就回去再玩几局、每局玩得更久一点。

---

### 第 5 步 · 训练模型

**干什么**：让神经网络从你的数据里学规律。**全部在本机跑，不联网、不需要服务器。**

**怎么跑**

```powershell
python 5_训练模型.py
```

不填参数时，它用 `5_训练模型.py` **文件开头那个 `DATA_DIRS` 列表**里写死的数据集
（现在指向 `dataset\20260918_merged`）。想换数据就改那一行，或者临时指定：

```powershell
python 5_训练模型.py --session dataset/run01 dataset/run02     # 多个会话一起练
```

**要跑多久**：RTX 4060 Laptop 上大约 **3 分钟一轮**，默认最多 60 轮、连续 15 轮没进步就自动停。
所以完整跑一次可能一到两小时。屏幕上有一条**实时进度条**，五秒刷一次。
想先快速试一下，加 `--epochs 5`。

**产出**：`runs/<名字>/` 目录，名字自动生成为 `会话名_时间戳`，里面有

| 文件 | 是什么 |
|---|---|
| `best.pt` | **最终模型权重**（效果最好的那一轮） |
| `model_meta.json` | 部署要用的参数，`9_自动玩.py` 读它 |
| `log.txt` | 完整训练日志 |
| `curves.png` | 训练曲线图，可以直接打开看 |
| `history.csv` / `metrics.json` | 每一轮的指标数字 |

---

### 第 6 步 · 看效果

**怎么跑**

```powershell
python 6_评估效果.py
```

不填参数时它自动挑「效果最好的模型 + 最新的会话」。

**重点看这 4 个数字**（这才是判断能不能上线的关键，光看准确率会被骗）：

| 指标 | 什么意思 | 期望 |
|---|---|---|
| **换道动画负样本 → N** | 角色正在换道动画里，模型有没有管住手不再按方向键 | 越高越好，> 0.90 |
| **该换道却输出 N** | 本来该按方向键、模型却不动 —— 这种错**游戏里直接撞死** | 越低越好，< 10% |
| **障碍还远负样本 → N** | 障碍刚出现、还早，模型有没有忍住 | 越高越好 |
| **单张推理延迟** | `9_自动玩.py` 要跑到 40fps，每帧只有 25ms 预算 | < 25ms |

它还会按**游戏速度分桶**打印准确率 —— 高速段的准确率才是上线后的真实水平。

---

### 第 7 步 · 让模型自己玩

**先干跑**（不发按键，只看它预测什么，安全）：

```powershell
python 9_自动玩.py --dry-run
```

**确认预测合理之后**，去掉 `--dry-run` 正式开玩：

```powershell
python 9_自动玩.py
```

`9_自动玩.py` 默认用**文件开头 `MODEL_DIR` 那一行**写死的模型目录
（现在指向 `runs\20260918_merged_20260918_1822`）。想换模型就改那一行，
或者命令行加 `--run runs/别的名字`（想先看有哪些模型：`python 9_自动玩.py --list-runs`）。

跑起来以后会弹两个窗口：

* **主窗口**：关掉游戏画面的实时预览
* **CAM 窗口**：热力图，看模型这一帧在盯着画面哪里（不想要就加 `--no-cam`）

没把握的话，还能先标定一下置信度阈值：`python 9_自动玩.py --calibrate`

## 五、9 个脚本速查表

`paoku/` 下的 9 个入口脚本按工作流顺序编号，**在 PyCharm 里右键 → Run 即可**。

| 文件 | 干什么 | 要模拟器吗 | 要参数吗 |
|---|---|---|---|
| `1_采集自检.py` | 采集前自检：抓帧是否有效、模拟器卡没卡死 | 要 | 不用 |
| `2_采集数据.py` | **采集数据**（F8 暂停 / X 撤销 / F10 退出） | 要 | 建议 `--session run01 --hook-state` |
| `3_复核数据.py` | 复核：删坏样本、改错标签 | 不要 | 按提示输入目录 |
| `4_速度覆盖度.py` | 看速度分布覆盖够不够 | 不要 | 把会话目录当参数传 |
| `5_训练模型.py` | **训练模型**（本机 GPU） | 不要 | 不用（用 `DATA_DIRS`） |
| `6_评估效果.py` | **看效果**：准确率、两类负样本表现、推理延迟 | 不要 | 不用 |
| `7_时序诊断.py` | 诊断「动作偏早」：模型比人提前多久开始动 | 不要 | 不用 |
| `8_注意力可视化.py` | 看模型在看画面哪里（Grad-CAM 热力图） | 离线不要 | `--live` 才是实时 |
| `9_自动玩.py` | **让模型自动玩** | 要 | `--dry-run` 先看预测 |

> 只想知道能不能用：跑 `5` → `6` 就够了。
> `7` `8` 是「效果不理想，想知道为什么」时才用的诊断工具。

## 七、采集建议（想练得好，重点看这段）

| 建议 | 为什么 |
|---|---|
| **每类攒到 800~1000 个样本** | A/D/N/S/W 五个数都得到这个量级，否则模型会偏向多的那类 |
| **每一局尽量玩久一点** | 游戏会越跑越快，高速段的画面才是模型最缺、最需要的；开局几秒的数据价值很低 |
| **分 3~5 局采，每局一个会话名** | 速度覆盖更均匀，划分训练/测试时也不容易互相污染 |
| **别在菜单、死亡结算里采** | 那些画面会教坏模型。忘了暂停就用 `3_复核数据.py` 按 `f` 批量删 |
| **攒齐了再训练** | 训练需要所有会话一起做「按时间段均衡划分」；本机一轮 3 分钟，攒够一次练完最省事 |

**已经踩过的坑**：早期几批数据速度中位数只有约 10 px/秒，最快也就 27~41 px/秒，
高速段占比不到 1%。结果就是**模型在高速段基本必死**。所以后面采集一定要玩得久。

## 八、出问题了

先看这几个最常犯的：

| 现象 | 怎么办 |
|---|---|
| 自检报「画面完全没有变化」 | 模拟器卡死了，重启模拟器 |
| 玩了两分钟各类计数还是 0 | 看状态栏是不是显示「已暂停」（误按了 F8），或者还在「等开局中」 |
| 训练时 `MemoryError` | 内存不够。加 `--workers 2 --batch-size 16 --prefetch 1` |
| `unrecognized arguments: --xxx` | 参数填到别的脚本上了（比如 `--no-cam` 是 `9_自动玩.py` 的，不能给 `5_训练模型.py`） |
| PyCharm 报 frida 相关错误 | 右下角解释器没切到 `wasd311` |
| `ImportError: attempted relative import` | 你直接跑了 `collector/` 里的文件。请跑 `paoku/` 下编号的那 9 个 |

## 附：和旧版的区别

旧版是 `caiji.py` / `shuju.py` / `trian.py` / `auto_wasd.py` 四个平铺脚本，已经全部删除。
主要问题与现在的改法：

| 旧问题 | 现在怎么解决 |
|---|---|
| 按下按键**之后**才截图（延迟 100~300ms），存的是动作已经发生的画面 | 抓帧线程常驻，按键只记时间戳，事后从环形缓冲**回溯**取帧 —— 结构上不可能取到动作之后的画面 |
| 每个样本只有一帧，分不清「该换道」和「正在换道」 | 每样本存 37 帧连续画面，训练时取 6 帧叠成 18 通道 |
| 随机划分，相邻帧泄漏到验证集，指标虚高 | 按时间段均衡划分 |
| 不知道「别动」信号怎么给 | N 类三个来源：手动按 `n` + 换道动画合成负样本 + 障碍还远合成负样本 |
| 部署时在换道动画里重复触发 | 模型侧学会输出 N + 部署侧 320ms **同方向**动作锁定 |
| 游戏越来越快导致分布漂移 | 记录每个样本的速度、出覆盖度报告、可按速度重加权 |
| 采集失误无法补救 | `X` 键现场撤销 + 事后复核工具 |
| 抓帧依赖 ADB（本机会挂起） | PrintWindow 直接抓窗口，实测 40~56fps |
| 不知道游戏状态 | 直接读 IL2CPP 内存里的 `GameController` 状态变量 |
